# Установка, обновления и сайт

С версии 0.8.0 Veyra — обычная устанавливаемая программа: установщик `Veyra-Launcher-Setup-<версия>.exe`, ярлыки, удаление через «Параметры → Приложения» и обновления, которые ставятся сами. Сайт **https://veyra-launcher.com** (папка **site**, PHP 7.2+) раздаёт установщик, отвечает лаунчеру на проверку обновлений и выкладывается одной командой.

## Как устроена установка

По умолчанию лаунчер ставится в `%LOCALAPPDATA%\Programs\Veyra Launcher` — права администратора не нужны, папку можно выбрать в окне установщика.

    Veyra Launcher\
      Veyra Launcher.exe            — маленькая заглушка, на неё ведут ярлыки и закреп на панели задач
      Uninstall Veyra Launcher.exe  — деинсталлятор (запись в «Приложениях» ведёт на него)
      veyra-install.json            — какая сборка текущая и какие ярлыки выбраны
      app-0.8.0-<хеш>\              — сама программа этой версии
      packages\                     — скачанный установщик новой версии, пока она не открылась

Каждая версия живёт в своей папке `app-<сборка>`. Заглушка запускает ту, что записана в `veyra-install.json`. Поэтому обновление не трогает файлы работающей версии: занятых файлов и наполовину обновлённой программы не бывает.

Сборки, миры и скриншоты лежат в «Документы\Veyra Launcher», настройки — в `%APPDATA%\veyra-launcher`. Установка, обновление и удаление их не затрагивают; удалить настройки можно галочкой в окне удаления.

## Как обновляется лаунчер

1. Лаунчер спрашивает https://veyra-launcher.com/update.php при запуске и раз в шесть часов.
2. Найдя новую версию, он скачивает её установщик в `packages\`. Если связь оборвалась, загрузка продолжается с места остановки, до четырёх попыток подряд. Файл сверяется по SHA-256 с сайта.
3. Скачанный установщик запускается без окна (`--update`) и распаковывает новую версию рядом с работающей, а потом переключает `veyra-install.json`. При любой ошибке переключения не происходит, и работает прежняя версия.
4. После перезапуска лаунчера (кнопка «Перезапустить и обновить» или следующий запуск) открывается новая версия. Она удаляет прежнюю папку и скачанный установщик.

Режимы в настройках лаунчера:

- **Уведомлять** (по умолчанию) — лаунчер сообщает о новой версии, а скачивает и ставит её по кнопке.
- **Не показывать** — ничего не проверяет сам, кнопка «Проверить сейчас» остаётся.
- **Автоматически** — скачивает и ставит в фоне, новая версия откроется при следующем запуске.

Переносимые версии 0.7.x (одиночный EXE) тоже получат обновление: они скачают установщик и запустят его. Откроется обычное окно установки с пометкой о переходе; после «Установить» лаунчер запустится уже установленным, сборки и настройки останутся на месте. Версия 0.7.2 адреса обновлений не знала — с неё нужно один раз скачать установщик с сайта.

## Как выпустить новую версию

1. Поднимите номер версии в **package.json**.
2. Допишите в **CHANGELOG.md** раздел `## <версия>` со строками `- что изменилось` — это список «Что нового» на сайте и в лаунчере (до 12 пунктов).
3. Выполните `npm run release`.

Команда соберёт приложение и установщик (`npm run dist`), загрузит установщик на сайт частями, сервер сверит SHA-256 и сделает версию текущей. В конце скрипт сам запросит update.php и убедится, что лаунчеры получат именно этот файл.

- `npm run release:upload` — выложить уже собранный `dist/Veyra-Launcher-Setup-<версия>.exe`;
- `npm run release:upload -- --draft` — загрузить черновиком, без публикации;
- `npm run release:upload -- --replace` — заменить файл уже выложенной версии.

То же можно сделать в панели https://veyra-launcher.com/admin/: перетащите установщик из папки dist в карточку «Новая версия».

## Как выложить сайт

    npm run site:deploy

Команда собирает папку site и отправляет на сервер изменившиеся файлы через панель (вход по ключу из `.veyra-site.json`). Сервер принимает их во временную папку, сверяет SHA-256 и переносит на место все вместе. Затем он убирает лишнее: файлы прошлой выкладки, которых больше нет, и всё постороннее в `assets/`. В конце скрипт проверяет, что страница, картинки и шрифты открываются. Папки `data/` (версии, статистика, вход) и `downloads/` (установщики) не трогаются никогда.

### Разовое исправление: картинки не грузятся

На сервере архив сайта распаковался **внутрь папки `assets/`**: там лежит вторая копия сайта, а картинки оказались по адресам `/assets/assets/…`. Старая панель на сервере ещё не умеет выкладку командой, поэтому один раз нужно вручную:

1. Выполните `npm run site` — получится `dist/veyra-site.zip`.
2. В файловом менеджере хостинга откройте **корень сайта** — папку, где лежат `index.php`, `update.php` и папка `downloads`.
3. Удалите там папку `assets` целиком (в ней только картинки, шрифты и лишняя копия сайта).
4. Загрузите `veyra-site.zip` в этот же корень и распакуйте его там с заменой файлов.
5. Проверьте https://veyra-launcher.com/ — логотип и картинки должны появиться.

Дальше сайт обновляется только командой `npm run site:deploy`. Если что-то снова окажется не на своём месте, она сама уберёт лишнее из `assets/`.

## Что где лежит на сервере

| Адрес | Что это |
|---|---|
| `/` (index.php) | Страница загрузки: версия, размер, дата, SHA-256, «Что нового», прежние версии |
| `/update.php` | Файл обновлений для лаунчера; каждая проверка учитывается в статистике |
| `/download.php` | Кнопка «Скачать»: считает загрузку и перенаправляет на файл. `?v=0.7.2` — конкретная версия |
| `/latest.json` | Тот же файл обновлений статическим файлом |
| `/downloads/` | Установщики (и переносимые EXE прежних версий) |
| `/admin/` | Панель: версии, загрузка, статистика, доступ |
| `/data/` | Список версий, статистика, вход, список файлов сайта. Все файлы — PHP-заглушки, по адресу отдают пустоту |

## Формат файла обновлений

    {
      "version": "0.8.1",
      "published": "20 октября 2026",
      "notes": ["Что изменилось"],
      "page": "./#download",
      "windows": { "url": "download.php?v=0.8.1&via=update", "sha256": "…", "size": 107000000 }
    }

Ссылки относительные — они считаются от адреса самого файла обновлений.

## Защита

- Лаунчер принимает только адреса HTTPS и запускает скачанное только после совпадения SHA-256.
- Установщик и деинсталлятор не просят прав администратора. Деинсталлятор не запускает посторонних программ: он переносит себя во временную папку и удаляет установку сам — так на него не реагируют антивирусы.
- Сервер сам считает SHA-256 загруженных файлов и сверяет их с посчитанными у вас. Установщик без заголовка EXE не принимается.
- Ключ панели хранится только в `.veyra-site.json`, на сервере — его хеш. Выкладка кода сайта доступна только по ключу, из браузера по паролю её не сделать. После пяти неверных попыток вход с адреса замирает (от 15 секунд до 15 минут).
- Если ключ утёк: удалите `.veyra-site.json`, выполните `npm run site` (появится новый ключ), загрузите `site/inc/config.php` на сервер вручную, а в панели нажмите «Выйти на всех устройствах».

## Проверки

- `node scripts/installer-check.js` — установщик целиком: тихая установка и установка через окно, ярлыки и запись в «Приложениях», запуск через заглушку, обновление с сайта с обрывом связи посередине, установка в фоне, перезапуск в новую версию, уборка прежней, удаление. Реестр и ярлыки пишутся в отдельные тестовые места.
- `node scripts/update-check.js` — модуль обновлений лаунчера.
- `node scripts/site-check.js` — папка site: файлы, якоря, иконки, SEO-теги, хеш ключа.
- `node scripts/site-php-check.js` — серверная часть на встроенном сервере PHP (путь к php.exe — в переменной PHP_BINARY), включая выкладку сайта с уборкой копии в `assets/`.
