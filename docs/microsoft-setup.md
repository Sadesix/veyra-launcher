# Подключение Microsoft-входа к Veyra

**Разработка привязки приостановлена.** В текущей версии элементы Microsoft скрыты из меню. Код и эта инструкция сохранены для будущего возобновления; текущий интерфейс позволяет удобно сменить локальный ник.

Вход реализован через код устройства: Veyra показывает короткий код, а пользователь подтверждает его в браузере Microsoft. Пароль в лаунчер не вводится. Затем Veyra получает Xbox, XSTS и Minecraft-сессию и загружает игровой профиль.

У текущей сборки ещё нет зарегистрированного Microsoft Client ID. Поэтому кнопка входа будет доступна после настройки приложения. Регистрация и доступ к Minecraft API выполняются владельцем Veyra в его аккаунте.

## 1. Зарегистрировать приложение

1. Откройте [официальную инструкцию Microsoft](https://learn.microsoft.com/en-us/entra/identity-platform/quickstart-register-app) и Microsoft Entra admin center.
2. Создайте регистрацию с названием **Veyra Launcher**. Выберите поддержку личных Microsoft-аккаунтов: **Personal Microsoft accounts only** или вариант, включающий личные аккаунты.
3. В **Authentication → Advanced settings** включите **Allow public client flows**. Лаунчер использует публичный клиент и device code flow; Client Secret ему не нужен.
4. Скопируйте **Application (client) ID** со страницы Overview. Это публичный UUID, а не пароль.

Device flow описан в [документации Microsoft](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-device-code). Veyra использует authority `consumers` и разрешения `XboxLive.SignIn offline_access`.

## 2. Указать Client ID

После возобновления интерфейса: **Профиль → Microsoft → Настройка Microsoft-входа для Veyra → Application (Client) ID → Сохранить ID**. Флаг интерфейса — `MICROSOFT_UI_ENABLED` в `renderer/renderer.js`; сейчас он выключен.

При сборке для всех пользователей задайте `clientId` в `main/microsoft-config.json` и пересоберите `.exe`. Для разработки можно задать переменную `VEYRA_MICROSOFT_CLIENT_ID`. Сохранённое значение из интерфейса имеет приоритет.

При изменении эффективного Client ID сохранённая Microsoft-сессия удаляется и потребуется новый вход.

## 3. Проверить доступ к Minecraft

Регистрация Microsoft сама по себе не гарантирует доступ приложения к Minecraft API. Если вход Microsoft и Xbox проходит, а Minecraft возвращает HTTP 403, Veyra показывает ошибку доступа приложения. Проверьте возможность одобрения своего приложения через [поддержку Minecraft](https://help.minecraft.net/). Порядок одобрения может меняться; получение доступа не выполняется автоматически из лаунчера.

Для проверки нужен аккаунт с доступом к Minecraft Java Edition и созданным игровым профилем. Если профиль не найден, Veyra предложит проверить покупку или создать профиль на minecraft.net. Ограничения детского аккаунта настраиваются в семье Microsoft/Xbox.

## Ник и сохранение входа

- **Локальный ник:** редактируется прямо в профиле и сохраняется клавишей Enter. Используется при следующем запуске. При смене ника меняется локальный UUID игрока.
- **Microsoft-ник:** кнопка «Сменить ник на сайте» открывает официальный профиль Minecraft. После изменения нажмите «Обновить» в Veyra.
- **Сессия:** находится в `microsoft-session.bin` в пользовательской папке приложения и зашифрована Windows DPAPI. Паролей, Client Secret и открытых токенов в `settings.json` нет.
- **Выход:** удаляет сохранённую сессию и переключает лаунчер на локальный профиль. Уже запущенная игра продолжает работать до закрытия.

## Проверки

`npm run check:auth` проверяет протокол на тестовых ответах. При выключенном интерфейсе `npm run check:auth-ui` проверяет локальный ник и скрытие Microsoft-функций. В скрипте сохранены проверки отмены, смены аккаунта, шифрования, обновления профиля и восстановления сессии для будущего включения. Настоящий вход в Microsoft в этой сборке ещё не проверен.
